## Accepted implementation shape

1. Before constructing a WebSocket pair, accepting a socket or calling upstream, parse query mode: absence defaults to `transcribe`; exactly one `transcribe` or `translate` is valid; empty, unsupported or duplicate values return static 400. Reject duplicate target query values as ambiguous; capture its optional single value through the existing language mapper. Preserve missing-key and non-upgrade behavior.
2. Call `geminiLiveSession(env, mode, target)` once before the asynchronous handshake. Serialize its setup immediately into a captured immutable server setup frame, so later environment mutation or client fields cannot change it.
3. Add an optional captured setup argument to `attachGeminiProxy`. Existing two-argument bridge consumers retain their current behavior. The actual paid fallback handler always supplies the captured server setup; no public handler opts out.
4. On the client-to-upstream serialized queue, decode the first frame using the existing text/Blob/ArrayBuffer/view converter. Require a JSON object with exactly one own `setup` property whose value is an object. Ignore all its setup contents and send only the captured server frame. Malformed, non-object, mixed setup/audio, missing setup or invalid setup-value frames close both peers with a static protocol/policy error before forwarding client content.
5. Decode later client messages in the same queue and reject any own top-level `setup` field, including null/mixed/Blob forms. Forward ordinary valid JSON input/audio/end frames unchanged. No new audio/tool protocol allowlist or provider pricing/model assumption. Reject malformed client JSON rather than forwarding it. Closing marks the bridge closed before closing either peer, suppressing queued or delayed Blob work afterward.
6. Upstream acknowledgement/data decoding, ordinary audio ordering, close-code normalization/propagation and generic bridge compatibility remain covered. Neither credentials nor frame contents enter new logs/errors.
