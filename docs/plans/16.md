## Risks

- Stop followed immediately by Start must not let a prior worker stop the replacement recognizer or reset its button/state. Each session owns a stop Event and local recognizer; serialize provider setup/cleanup without blocking Tk.
- Azure SDK startup/stop may block. Workers remain daemon threads; window close invalidates queued work and cancels Tk timers without joining the SDK on the main thread.
- Tk is thread-affine. Worker and SDK callbacks enqueue plain event data; only the main-thread drain touches widgets or schedules Tk callbacks.
- Final rendering must replace provisional text and preserve earlier finalized history.
- Preserve every existing widget, style, geometry and layout declaration exactly; this change has no visual design scope.
