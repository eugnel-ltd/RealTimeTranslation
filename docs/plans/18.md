## Proof

- Tail replacement: begin answering a short question, then append enough distinct multipart continuation segments inside the tail window to exceed 500 words. The final answer request must contain the preamble, every middle segment and final subpart in exact order. Old code drops an earlier middle chunk.
- Initial extraction: delay the question-start response after a short input, then add long multipart continuations before it resolves. The resulting answer request must contain the entire contiguous question at completion. Old code uses the capped extension and drops the middle.
- Unknown start: with more than 500 words in the generous fallback window, extraction keeps all eligible segments while the detector remains capped.
- Bounds: a known start older than three minutes cannot pull expired history into a request. The Worker rejects combined caller prompt inputs above 256 KiB UTF-8 with 413 before profile/provider calls; boundary-sized inputs and complete long questions remain intact.
- Detection: inputs to question-presence and question-start detection keep their existing 500-word cap; existing oversized-single-segment semantics remain unchanged.
- Provider count: the change adds no detector, extraction or answer calls; only context selection changes.
- No JSX/CSS changes, no dependencies, bindings, secrets, provider contracts or spend changes.

## Risks and limits

- A supplied question start may be absent from the bounded history. Fall back to the complete eligible window rather than inventing a partial slice.
- The three-minute floor and 256 KiB Worker input refusal are intentional safety bounds. Do not silently truncate text to satisfy the Worker limit. Profiles keep their existing separate 200 KiB upload limit.
- Preserve existing segment IDs so repeat protection and tail start ownership remain stable.
- Live provider and microphone smoke checks are outside this local context-selection fix and must be disclosed.
