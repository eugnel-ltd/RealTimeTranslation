## Risks

- API compatibility: optional missing fields retain existing defaults; only malformed JSON and supplied fields of invalid types are rejected. Unknown keys remain allowed. No Access, provider credential, binding or paid integration changes.
- Validation cannot turn unexpected server faults into client errors: a dedicated input-error type is mapped to fixed JSON 400; unrelated exceptions retain the existing 500 handling.
- Cancellation can race completion: cancellation is idempotent, abort listeners are removed, reader cancellation is awaited or safely observed, and completed/cancelled streams emit no later events. Use deterministic pending-reader tests.
- Browser/Worker global types differ: separate compiler projects preserve checking of all source and tests rather than adding blanket suppression or excluding tests. Lint rules must be useful without forcing unrelated App/UI edits.
