## Risks

- Private data escape: construct fixed failure objects and allow-listed route/status/kind tags only. Never capture original error/name/message/stack, request/URL/query/headers, transcript/profile or provider content. No browser SDK/client tracking.
- Reporting outage: missing/malformed DSN is off; capture has an injected two-second AbortSignal deadline, no retry, and failures cannot delay or alter the response. No global fetch interception.
- Authentication: all health routes remain under existing `/api/*` Access and request budgets; monitoring uses a narrow service identity rather than an exemption. Fixed-origin/manual redirects prevent credential forwarding.
- False completion: metadata and package version prove configuration only. An authenticated live run and actual deployed identity are separate evidence. Baseline stays missing without it.
- Spend/noise: use the existing free Sentry plan and self-hosted runner; one bounded capture per server failure, no capture for expected 4xx/quota/cancellation. No new bindings, crons, paid services or user analytics.
