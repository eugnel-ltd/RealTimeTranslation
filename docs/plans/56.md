# Refuse explicit foreign origins on owner-mode API mutations

Intent: RTT #56. Bug-fix/security, level2; no spending, activation or visual changes. The customer resolver already requires an exact Origin on mutations, but disabled customer mode returns legacy context before that check. Owner-mode paid POSTs and profile PUTs therefore accept an explicit foreign browser Origin.

## Boundary and integration

Add a small shared guard at the start of `routeApi` in `worker/src/index.ts`, after method capture/logging and before handler/body dispatch. For methods other than GET/HEAD, reject a present Origin unless it exactly equals the canonical origin of the trusted request URL; use a fixed403 response. Preserve absent Origin for legacy nonbrowser Access clients and exact same-origin requests. Do not add Content-Type requirements, forwarded-header trust, suffix/wildcard matching or development exceptions. GET, HEAD and the independently fixed WebSocket GET keep their current behavior.

Inspect account consumer fa0798f with its author before implementation. It resolves the strict customer context in `worker.fetch` before entering `routeApi`; auth callbacks and the signed internal eraser dispatch separately. Keeping this new guard inside `routeApi` preserves their existing customer required-Origin/error contracts and protocol boundaries. Access and rate checks stay before all API dispatch. The account consumer will ordinarily merge this separate fix and verify that ordering remains intact.

## Tests before source

Add one new typed defensive router regression file without editing existing tests. Exercise every implemented owner paid POST and profile PUT with injected provider/KV operations only. Foreign/sibling, opaque null, malformed and duplicate/coalesced explicit Origins must return403 before body consumption, provider calls or profile writes. Valid request bodies make the old failures meaningful; preserve passing controls for same/missing Origin, nondefault canonical port, Access-first denial and GET/HEAD compatibility. Forwarded headers must not change request URL authority. Use the actual router and a locally signed Access/JWKS fixture where useful; no live or separate demonstration probes.

Run and inspect old-source failures, then typecheck, lint and trusted staged-candidate secret scanning before freezing the new file. Root authorizes reuse of the already unavailable vendor lane without new waits. Apply the narrow guard without changing frozen tests; run targeted/full tests, typecheck, lint, build and Worker dry packaging. Check old-test equality and secret/owner/diff guards.
